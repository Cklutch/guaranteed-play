- Removed `pages_archive/7_Live_Rankings.py` — functionally superseded by `Home.py`, kept around only as dead weight.

- Removed `pages_archive/8_Tier_Desperation.py`, `pages_archive/2_Player_Cards.py`, `pages_archive/5_Draft_Lab.py` — three more shelved pages, not needed and not being revived.
- Removed `draftkit/recommendation_explainer.py` and `draftkit/model_evaluator.py` — orphaned once Player Cards and Draft Lab were gone (nothing else imported either).
- Kept (do not delete despite being paired with the pages above): `draftkit/conviction.py`, `draft_lab.py`, `draft_simulator.py`, `draft_simulation.py`, `opponent_model.py`, `draft_strategy.py` — all still imported by `scripts/run_runtime_profile.py` (a real runtime-profiling dev tool), and `draft_simulation.py` additionally by the still-shelved `pages_archive/9_Component_Audit.py`.
- Trimmed `app.py`'s page list (Player Cards, Tier Desperation) to match. Note: `app.py` is itself a dead, unused alternate Streamlit entry point — 4 of its remaining 6 page paths already pointed at `pages/` instead of `pages_archive/` before this change and still do; the real nav is `Home.py`'s `TOOL_PAGES` dropdown (`draftkit/ui_helpers.py`). Worth deleting `app.py` outright in a future pass.
- Fixed a real bug in `draftkit/championship_equity.py` found while sanity-checking it after the Component Audit removal below: several functions called `safe_float(x)` with no explicit default, then checked `if result is None:` to detect missing data -- but `safe_float()`'s own default is `0.0`, not `None` (`draftkit/common.py`), so a missing value silently became a real `0.0` and the fallback branch never fired. Worst case: `calculate_ceiling_score`'s `ceiling_projection` input is 0% populated in `load_players_df()`, so every player fell through to real math on a false `ceiling=0.0` instead of the intended graceful fallback, driving `ceiling_score` -- 25% of the total weight, the single largest component -- to a flat `0.0` for the entire ~3,900-player pool (confirmed against Jahmyr Gibbs: real 337.2-point projection, top overall pick, scored identical to a replacement player). A second real-impact instance in `calculate_breakout_probability` wrongly applied an elite-top-12-ADP penalty to the ~83% of players missing `adp_rank` data. Fixed by passing `default=None` explicitly at every affected call site.
- Rewired `ceiling_score` and `sportsbook_advantage_score` (2026-08-27) to reuse real, already-live signals instead of the dead `ceiling_projection`/`floor_projection`/`sportsbook_projection` columns:
  - `ceiling_score` now reuses the exact upside signal powering Home.py's live Ceiling view (`role_usage_td_score` + `volatility_diagnostic` from `risk_variables.csv`, plus an event/big-play archetype lift), merged in by player_name. First pass dropped Home.py's percentile-of-relevance damping as "a different job" -- that was wrong: undamped, it inverted the whole ranking (deep-bench/practice-squad names at the top, Gibbs/CMC/Chase at the bottom), exactly the "TD vulture" failure Home.py's own comment says the damping exists to prevent. Added the same damping back (`_ceiling_relevance`, a projection-points percentile computed vectorized before the per-row loop).
  - `sportsbook_advantage_score` now merges real data from `data/processed/sportsbook_vs_adp_comparison.csv` (300 real players, `sportsbook_half_ppr_points`) instead of the mock `sportsbook_provider.fetch_sportsbook_projection_data()` path (which only covers 3 hardcoded players). Wiring in real data exposed a second, separate, pre-existing bug in the scoring formula itself: `edge_pct = (sportsbook - projection) / projection` blows past the 100 clip ceiling for any player with a small projection baseline (backup RBs projected at 17-35 points swing 100%+ on a modest absolute point difference), the same class of bug CLAUDE.md documents Base Value's own market component was built to avoid. Fixed by switching to a percentile rank of the raw point-edge across the pool (mirroring Base Value's `adp_pct = (-adp).rank(pct=True)` pattern) instead of a per-player ratio.
  - **Follow-up fix, same day**: normalized the edge within `SPORTSBOOK_EDGE_TIER_COUNT` (6) ADP-quantile tiers (`pd.qcut` on `adp_rank`, pulled from the same `sportsbook_vs_adp_comparison.csv` row as the edge itself) instead of ranking across the whole pool -- "does the market like this player more than typical for someone drafted around here," not an absolute tier-conflated edge. Verified as a real, measurable improvement, not just a plausible-sounding change: Ja'Marr Chase's score moved 26.8 -> 52.1, Christian McCaffrey's 17.6 -> 39.6, both crossing to roughly neutral. Not a full fix, though, and this is an inherent limit of discrete tiers rather than a bug: the underlying trend is smoothly monotonic in ADP rank (round 1-2 mean edge -31.0, round 3-5 -22.3, round 6-10 -11.3, round 11+ -7.5), not a clean step function, so 6 buckets approximate it without fully flattening it -- a player near the top of a ~47-player tier can still sit slightly below tier-mates drafted a bit later in the same bucket. `sportsbook_advantage_score` is now the dominant driver of the top-15 (elevated in 15/15, correlation +0.29 with the final blended score) -- more so than `ceiling_score` (correlation -0.14, elevated in only 4/15). A finer-grained or regression-detrended (edge ~ adp_rank residuals) version would close more of the remaining gap if it matters enough to pursue further.
- Revived `pages_archive/9_Component_Audit.py` as `pages/3_Component_Audit.py`, then removed it again the same day after inspecting what it actually produced: its `FEATURE_SPECS` audit a legacy `MASTER_COMPONENT_COLUMNS` scoring pathway (`draft_analysis.py`), not the real Base Value engine that drives `final_score` today (`base_value_vor/projection/market/risk_component`) -- 2 of 9 "features" (Workload, Offensive Environment) had no matching column at all, 2 more (Durability, Future Availability) returned constant/zero output, and Championship Equity showed a suspicious -0.88 correlation against final_score. Fixing it to audit the real engine would be a rewrite, not a patch, and would mostly duplicate what `test_base_value_weights.py` already checks more rigorously. Removed the page and its dedicated `draftkit/ranking_component_audit.py` module (no other importer). `championship_equity.py` and `data_pipeline.py` were untouched -- both have real dependents elsewhere (`conviction.py`, `draft_grades.py`, `draft_simulator.py`, `recommendation_audit.py`, and `draftkit/scripts/`), though `data_pipeline.validate_player_data()` specifically is now unused dead code inside that otherwise-live file.
